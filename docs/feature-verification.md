# 전체 기능 검증표

## 2026-11-14 Windows 좌표 지정·장소 등록 후속 수정

- Windows 좌표 지정은 기존 네이티브 위치 저장 명령을 재사용하여 실제 Roblox 창에서 클릭·영역 드래그를 받는다. 앱에서 누른 마우스는 무시하고 다음 클릭을 받으며 Esc, 취소, 포커스/창 변경, 작업 시작, 세션 종료 시 폐기한다. 게임 클라이언트 좌표로 정규화하고 저장 성공 응답만 화면에 반영한다. Linux/macOS의 이미지 선택은 유지한다.
- Windows OCR의 개별 단어를 같은 줄의 인접한 이름·시설명으로 인식한다. 표시명과 계정명이 함께 보이면 두 관측이 같은 실제 발을 가리켜야 한다. 다른 줄·멀리 떨어진 글자·사이에 낀 단어·중복 이름을 임의로 합치지 않는다. 장소는 자기 이름·몸·발·지면과 목적지 표식이 함께 보여야 등록한다.
- 데스크톱 이동은 기존 키보드 변환 경로에 방향 벡터를 전달한다. 모바일 조이스틱 위치를 요구하지 않으며 점프는 Space로 전달한다. 이름은 자기 캐릭터 식별용임을 설명하고 공통 위치에 한 번만 표시한다. 저장된 장소와 작업 실패 메시지를 이동 화면에 표시한다.
- WGC 관측은 실제 받은 프레임 시각을 사용한다. 캡처 요청이 오래 걸렸다는 이유만으로 새 프레임을 폐기하지 않는다. 읽기 전용 장소 관측은 Windows 전경 전환을 요구하지 않으며, 장소 파일 저장 실패 시 이전 메모리를 복원한다.
- 로컬 검증: Rust 200개·UI 60개 통과, Windows 전체 라이브러리·테스트 타입 검사 통과. 실제 worker 소스에 OS 어댑터를 대체한 검사는 읽기 관측·실제 프레임 시각·선택 중복/취소·영역 결과를 확인한다. Windows 실기에서 실제 마우스/게임 길찾기 성공은 아직 미검증이다.

## 2026-11-14 Windows 보고 이후 수정

이 절은 아래 과거 빌드·실기 기록보다 우선한다. 이전 빌드 성공은 이번에 보고된 Windows 실제 게임 입력이나 전체 자동화를 검증한 증거가 아니다.

- Windows 숨김 데스크톱과 `PostMessage` 입력을 제거했다. 사용자가 Windows 전경 동작을 허용했으므로 일반 데스크톱의 Roblox를 실행하거나 기존 창에 연결하고, 실제 `SendInput`을 사용한다. 시작 시 게임 창을 활성화하고 이후 포커스를 잃으면 새 입력을 차단한다. 이미 누른 키·버튼은 해제한다. 외부에서 실행한 Roblox는 연결 해제 시 종료하지 않는다. Windows 미리보기는 읽기 전용이며 실제 창에서 직접 조작한다.
- 초기 연결·관측·미리보기가 같은 캡처 재시도 경로를 사용한다. 실패하면 입력 준비 상태를 해제하고 500ms 간격으로 재시도하며, 성공하면 연속 실패 횟수를 초기화한다. 5회 연속 실패한 경우에만 세션을 종료한다. OCR/작업 입력 오류는 해당 작업을 중지하고 게임 연결을 유지한다.
- Windows/macOS/Linux가 중복 구현하던 관측 만료 처리를 Rust 공통 경로로 합쳤다. 캡처가 OCR 시작 시점에 300ms 이내여야 하며 OCR에는 별도 최대 5초 처리를 허용한다. 판단 후 입력 시작 제한은 300ms다. 촬영 시각은 따로 보존해 릴링 예측·이동·점프 측정에 사용한다. 점프 물리 검사는 여전히 실제 촬영 시각 기준으로 신선한 화면을 요구한다.
- 설정은 Rust 검증·저장이 성공한 뒤에만 JS 기준값으로 반영한다. 거절 응답에는 기존 설정을 반환한다. UI의 낚시 숫자 입력은 범위를 표시하고 잘못된 값을 되돌린다. 시작 시 모드/온라인/바이옴 실패를 분리하고 기본 UI·게임 상태·버튼 연결을 유지한다. 설정 폴더 `diagnostics.log`에 시작, 게임 연결 상태, 오류를 크기 제한하여 남긴다.
- 업데이트·변경 로그는 `/releases/tags/dev-alpha`로 직접 조회한다. 과거 정식 PC/모바일 릴리스 목록은 사용하지 않는다. main을 수정하거나 기존 alpha를 삭제하지 않고 배포 채널을 분리했다. Mac workflow는 재사용 빌드가 되고 Linux/Windows/Android/Mac 모두 성공한 뒤 한 작업이 게시한다. 일부 플랫폼만 성공한 릴리스를 게시하지 않는다.
- Discord의 폐기된 `/macro/state` 주기 전송을 제거하고 `/macro/wait`와 `/macro/reply`로 교체했다. 봇이 요청한 상태/통계/로그만 보내고 로그는 100줄 이내로 제한한다. 대기 중 연결 해제·계정 변경 시 늦은 응답을 버린다. 실제 계정으로 메시지를 보내는 검사는 수행하지 않았다.
- 단일 실행 플러그인을 등록했다. 두 번째 실행은 기존 창으로 전달한다. 연결 없는 접속 안내 버튼은 게임 연결부터 시작한다. Windows의 새 실행은 저장한 서버 링크 또는 Sol’s RNG 공개 주소를 사용한다. 로비가 명확히 관측되거나 게임 밖 상태가 지속되면 복귀 판단을 시작한다. 작업 이름, 연결 상태, 재시도·오류·DUA 판단의 영어/일본어 표시를 보완했다.

설계 확인에 사용한 공식 설명: [Microsoft의 PostMessage 입력 한계](https://devblogs.microsoft.com/oldnewthing/20250319-00/?p=110979), [SendInput](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-sendinput), [Tauri 단일 실행 플러그인](https://v2.tauri.app/plugin/single-instance/). `SendInput` 성공은 Windows 입력 스트림 전달을 뜻하며, Roblox의 행동 성공은 이후 화면/로그로 확인해야 한다.

대상은 2026-11-13~14의 `dev` 작업 트리입니다. 이전 기준 커밋 `fbe8eee5558bd087a4d7f2fcedd28bd17c84841a` 이후의 전면 교체를 포함하며, 아래의 과거 APK·원격 실행 기록을 현재 작업 트리의 실기 결과로 바꾸어 계산하지 않습니다. 기준 기능은 정식 PC V3.0.5·모바일 V1.4.24입니다. 스나이핑과 iOS는 사용자 요청에 따라 제외합니다. 앱 안에는 AI 행동 모델을 넣지 않습니다.

공통 Rust 실행기에 낚시·팝핑·주기 아이템·상인·제작·메모리 매치·블러드 레인과 이동·판매·복귀를 연결했고, PC 브리지와 모바일 설정·오버레이도 같은 명령을 사용합니다. 이는 **구현과 연결의 상태**입니다. 신규 일곱 매크로와 실제 길찾기의 전체 모바일 실기는 아직 끝나지 않았습니다. 현재 요청에서 PC는 빌드·정적 검사·단위 검사만 수행하며 실제 게임 작동 검사는 모바일에서 진행합니다.

## 판정과 근거

- **구현·연결**: 실제 상태기계, 저장소, 입력·관측, UI 명령까지 이어진 코드를 말합니다. 성공 응답만 반환하는 대체 구현은 포함하지 않습니다.
- **단위 검사**: 공급한 상태·지도·픽셀·시간으로 코어를 확인합니다. 실제 게임 관측과 기기 입력을 대신하지 않습니다.
- **UI 회귀**: 실제 화면 코드와 시험용 IPC·시계로 호출·표시·저장·취소 경합을 검사합니다. 운영체제·서버·게임의 실제 동작은 별도입니다.
- **실제 PNG 재생**: 기기에서 얻은 화면의 인식을 확인합니다. 실시간 관측→입력→게임 반응이 이어지는 검사와 구분합니다.
- **실기**: 기기·OS·소스/APK·행동·결과를 기록한 범위만 인정합니다. 짧은 낚시나 앱 시작을 전체 기능·장시간 안정성의 통과로 넓히지 않습니다.

## 추가 연결 · 2026-11-14

모바일 입력은 Android 13 이상에서 A11yGameText의 접근성 게임 입력 연결을 사용해 Samsung 기본 키보드 같은 기존 입력기를 유지합니다. 구형 Android만 별도 Acrux IME 준비 경로를 사용합니다. 두 경로 모두 Roblox의 실제 입력칸과 전경·실행 세대를 검사하며, 입력 전송과 게임 결과 확인은 별도로 처리합니다. API 근거는 [Android 접근성 입력 연결](https://developer.android.com/reference/android/accessibilityservice/InputMethod.AccessibilityInputConnection)입니다. 이 문단은 구현 설명이며 실제 게임의 모든 검색·수량 입력이 통과했다는 기록이 아닙니다.

로그 감시는 Windows뿐 아니라 macOS와 Linux Sober 경로도 연결했습니다. Windows/macOS 경로는 [Roblox의 공식 로그 안내](https://en.help.roblox.com/hc/en-us/articles/360016022492-How-to-Retrieve-Roblox-Studio-Logs), Sober 경로는 이 기기의 실제 `data/sober/appData/logs`에서 확인했습니다. 초기 로그는 제한된 크기로 이어 읽으며, 지정한 플레이어가 확인되기 전에는 자동화 이벤트로 전달하지 않습니다.

화면은 캡처 시각과 입력 시작 기한을 함께 보존합니다. 모바일은 MediaProjection 타임스탬프를 사용하며 OCR이 오래 걸린 결과를 새 화면으로 취급하지 않습니다. 데스크톱은 캡처 호출 시작을 보수적인 기한으로 쓰고 WGC의 실제 프레임 시각도 확인합니다. 긴 드래그·보행은 시작 시 근거 유효성을 확인한 뒤 실행 세대/대상 검사로 완료·해제합니다.

명시적인 ‘기본 템플릿으로 되돌림’은 사용자가 수정한 해당 바이옴 목록도 기본값으로 교체합니다. 다른 바이옴은 보존하며 파일 쓰기에 실패하면 메모리 설정도 이전 값으로 되돌립니다. 실제 설정 파일의 재읽기와 저장 실패·실행 중 거절 회귀를 통과했습니다.

상인 자동 보정이 꺼져 있으면 저장 좌표를 보존하면서 현재 상점·상품·구매 결과를 검증합니다. 명시적 자동 보정은 토글과 관계없이 새 좌표를 저장합니다. 수동 채팅 확인은 지정 영역에서 실제 도착 문구를 읽고, 구매할 항목이 있는 상인을 각각 한 번씩 실행 큐에 넣습니다. 자동화 관련 22개 회귀를 통과했습니다.

모바일의 화면 없는 복구는 명시적 서버 접속·복귀 요청 또는 실제 `Client:Disconnect` 로그가 있을 때만 허용합니다. 일반 앱 전환과 Wi-Fi·블루투스·다른 앱의 끊김 로그는 복구 근거가 아닙니다. 재접속 요청은 실행 세대·단일 요청·시한·잠금 해제 검사를 통과해야 하며, 실제 새 입장 근거 전에는 복구 완료로 처리하지 않습니다. 취소·중지·완료 시 권한을 폐기합니다. 이 경로를 포함한 phone 회귀 17개를 통과했으며 최종 APK의 실기와 구분합니다.
